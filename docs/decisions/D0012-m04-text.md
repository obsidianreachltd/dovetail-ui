# D0012 — How M04 draws text

| Field | Value |
|---|---|
| ID | D0012 |
| Status | Accepted |
| Date | 2026-11-20 |

## Context

M04 needs single-line labels for `Button`, `Toggle` and the text control, with no editing. Full text arrives in [M06](../milestones/overviews/M06-text-and-input.md): font files, shaping, complex scripts, fallback, and sharp text at every scale.

[D0002](D0002-build-own-stack.md) allows no font or text library, so M04 needs some way to turn characters into pixels.

## Decision

M04 draws text with a **small built-in font written in Dovetail's own code**. It is a vector stroke font for printable ASCII, so it is Dovetail's own work with no licence questions.

- Glyphs are drawn into a glyph atlas texture at the window's scale, then painted as textured rectangles.
- Measurement is fixed-pitch: every character has the same advance width.
- The font, atlas and measuring function sit behind one interface. M06 replaces the font and the measuring, and keeps the atlas and the painting.

## Consequences

- M04 can show labels with no new dependency, on all three operating systems.
- Labels look plain, not like the platform's fonts, until M06.
- Characters outside ASCII are shown as a placeholder box until M06.
- M06 still has to build loading TrueType or OpenType outlines, shaping and fallback. This decision does not shorten M06.

## Alternatives considered

- **Parse TrueType outlines and rasterise them now:** real fonts from M04 on, but it pulls the start of M06 into M04 and makes M04 much larger.
- **A font crate (for example `fontdue` or `ab_glyph`):** quick and good-looking. But it goes against D0002, and M06 would replace it.
- **No text in M04:** it fails criteria 4 and 5, because the controls and the counter need visible labels.
